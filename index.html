    No configuration, no ticket, no downstream project. The classification is written once and every system that reads the graph responds to it — including the systems that did not exist when the tag was applied.

    One graph underneath all of it

    Qindral does not copy your metadata into another catalog. Source systems keep authority over what they know. Qindral holds the identity, the lineage and the classifications, and exposes one interface that both people and machines can act through.

    Identity that survives

    Every asset carries a durable identifier that outlives renames and platform migrations, so a table rename never silently breaks a control.

    Classification that propagates

    Column-level lineage carries sensitivity downstream automatically. Declassification is possible, but only as a recorded, approved act.

    Evidence by default

    Every enforcement decision is logged as it happens, so an audit becomes a query rather than a quarter of screenshot collection.

    Seven products, one graph

    Each writes to the same graph and reads the same classifications. Start with the pillar that hurts most, or run the lifecycle end to end.

    Known
    Stage 01
    Qindral Context
    Technical, business and operational metadata across structured and unstructured sources, with PII and SDE classification that downstream systems act on rather than merely record.
    Qindral Lineage
    Column-level lineage, deterministic where code can be parsed and AI-inferred where it cannot. This is the path every classification travels.
    Trusted
    Stage 02
    Qindral Quality
    Rules bound to critical data elements rather than to tables. Every failure arrives with its lineage, so blast radius is known before anyone asks for it.
    Qindral Signal
    Incidents, raised concerns and operational risk events, tied to the assets and the owners they actually touch instead of to a free-text description.
    Used
    Stage 03
    Qindral Catalog
    Reports, critical data elements, ownership and workflow. Search that matches intent rather than strings, and access requests that route to a team who can be paged.
    Protected
    Stage 04
    Qindral Privacy
    Purpose, consent basis and permitted use evaluated at query time. Subject access and erasure resolved through lineage instead of by hand, including the derived assets everyone forgets.
    Deleted
    Stage 05
    Qindral Horizon
    Retention clocks that start on events rather than calendars, deletion that cascades through derived tables, feature stores and vector indexes, legal hold that reliably overrides all of it, and a destruction certificate at the end.
